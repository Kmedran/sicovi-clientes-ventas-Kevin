1. RESUMEN Y JUSTIFICACION
Se completa la integración funcional de proveedores, compras e inventario:
mantenimiento y consulta de proveedores, borradores y recepción de compras,
anulación con reversión, existencias, movimientos, ajustes, navegación protegida,
auditoría administrativa e idempotencia con comparación de contenido.

Se elimina una ruta pública temporal que insertaba productos desde una petición
GET. El identificador tributario del proveedor es opcional conforme al manual;
cuando existe, conserva normalización y unicidad.

2. ESTADO PREVIO Y PRERREQUISITOS
Requiere las migraciones base de Manuel y YOURGEN-DB-001, YOURGEN-DB-001B y
YOURGEN-DB-002. No modificar migraciones históricas ni ejecutar procedimientos
destructivos para actualizar una base local.

3. MIGRACIONES NUEVAS

4. CAMBIOS DE BASE Y REGLAS
- `suppliers.tax_id` acepta NULL; los valores existentes no se modifican.
- El rollback de esa migración se detiene con un mensaje explícito si existen
  proveedores con `tax_id` NULL; primero debe corregirse esos datos con una
  operación autorizada.
- Los ajustes conservan un hash del contenido asociado a su clave de idempotencia.
- Reutilizar una clave con datos diferentes se rechaza.
- Confirmar una compra equivale a recibir toda la mercadería en V1; no hay
  recepciones parciales.
- Los ajustes se registran directamente como aplicados y admiten `opening`,
  `extraordinary_entry` y `count_adjustment`.
- No se limita a un único inventario inicial por producto.

5. COMANDOS DE ACTUALIZACION LOCAL
Confirmar primero la integración de Git y hacer respaldo privado.

cd [RUTA_LOCAL_DEL_PROYECTO]
.\scripts\php.ps1 artisan config:clear
.\scripts\php.ps1 artisan migrate --force
.\scripts\php.ps1 artisan migrate:status
.\scripts\php.ps1 artisan test

No ejecutar `migrate:fresh`, `db:wipe` ni `TRUNCATE` para actualizar una
instalación con datos.
