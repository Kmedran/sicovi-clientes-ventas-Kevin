SOLICITUD Y OBJETIVO
Cambiar el inicio de sesión al nombre de usuario corto real, independiente del
correo, y simplificar su presentación. El login deja de mostrar el logo y usa
USUARIO y CONTRASEÑA dentro de los campos; esos indicadores desaparecen al foco.
Se mantienen etiquetas accesibles, mensajes, POST y protección CSRF.

IDENTIDAD Y MANTENIMIENTO
users.username: identificador de acceso obligatorio, único y normalizado a
minúsculas. Longitud entre 3 y 40 caracteres ASCII; letras, números, punto,
guion o guion bajo, comenzando por letra o número. El mantenimiento Usuarios
permite crearlo y editarlo. No se obtiene recortando el correo en cada login.
El correo permanece como dato independiente, único y normalizado. Cambiar uno
de estos campos no cambia automáticamente el otro ni concede permisos.
Las contraseñas de cuentas normales conservan su política fuerte y hash.

MIGRACIÓN INCREMENTAL
2026_10_19_000005_add_usernames_to_users.php.
Añade username y sus restricciones de formato/unicidad. Asigna usuarios a las
cuentas existentes en orden de ID, partiendo del texto anterior a @ del correo:
convierte a ASCII y minúsculas, reemplaza caracteres incompatibles por guiones,
evita puntuación inicial y respeta el máximo de 40 caracteres. Para resultados
muy cortos utiliza usuario- y, si queda vacío, usuario. Las colisiones usan -2, -3,
truncando la base cuando corresponda. Se debe revisar el usuario final en el
mantenimiento después de actualizar.
Conserva correos, contraseñas/hash, estado, cargo y permisos individuales.
Las cuentas demo existentes reciben naturalmente sus usuarios cortos previstos.
No requiere borrar datos, recrear cuentas ni regenerar APP_KEY.

INSTALACIÓN NUEVA
Seguir README: preparar PostgreSQL/esquema, configurar entornos privados,
composer install, npm ci, claves solo para entornos nuevos, migrate --force,
SystemSeeder, administrador local y npm run build. DemoSeeder y usuarios demo
siguen siendo opcionales y sujetos a sus controles de entorno.

ACTUALIZACIÓN CONSERVANDO DATOS
1. Respaldar, detener escrituras y revisar el estado local de Git.
2. Conservar .env, .env.testing y APP_KEY existentes.
3. Instalar dependencias desde los locks y limpiar configuración cacheada.
4. Ejecutar migrate --force para aplicar 000005.
5. Ejecutar SystemSeeder si corresponde a la entrega, sin restituir preferencias.
6. Compilar recursos y limpiar caché de vistas.
7. Revisar usernames asignados en Usuarios y comprobar el acceso con usuario.
No usar migrate:fresh, db:wipe, truncados o reset de contraseñas como actualización.
La conversión de cuentas existentes no requiere volver a ejecutar el comando demo.

RECUPERACIÓN Y PENDIENTES
Ante un fallo, conservar datos y diagnóstico sanitizado; detener el relevo y
corregir la causa con una migración incremental cuando corresponda. No quitar
restricciones ni reconstruir la base para ocultar el problema. Una recuperación
desde respaldo exige un destino separado y autorizado según README.
La recepción en otra PC y la restauración cronometrada continúan pendientes.
